## 1. The sibling carries the fix (confirmed by reading and by running)

* **Read.** `evgen/polligen/tagged.py` `TaggedModel._amp2_table` (sibling
  lines 764-796 at `c0f86a8`) multiplies each wave by
  `phase = (-1.0) ** ((w.l // 2) % 2)` before the Clebsch–Gordan sum: +1 on
  L = 0 and L = 1, −1 on L = 2. That is the same relative phase as LiPolGen's
  `TaggedModel::build_amp2` (`src/core/tagged.cpp:394`, the
  `(-1)^floor(L/2)` comment at `src/core/tagged.cpp:420`).
* **Run.** With the carry-through switched off in a scratch copy of the dump
  script (output to the scratchpad, not the tree), `polligen`'s two spin-1
  model blocks agree with the committed LiPolGen re-pin to ≤ 2.28e−13 relative
  (§3). Against the PRE-fix `polligen` dump (the file at LiPolGen `47c5f7f`)
  the same blocks differ by up to 0.998 relative in `n_of_kc` and 1.78 in
  `p2_moment`, so the agreement is the fix, not an insensitivity.
* **Determinism check first.** The unmodified dump script, redirected to the
  scratchpad with the committed files as its starting state, reproduced all
  nine files in `validation/reference/` and `validation/README.md`
  byte-for-byte (`cmp`). So every difference below is the carry-through's
  removal and nothing else.
