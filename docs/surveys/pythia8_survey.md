## 2. How DIS is set up, and where a spin weight can enter

**Canonical setup** — `examples/main341.cc:29-54`:
```
Beams:frameType = 2 ;  Beams:idA = 2212 / eA ;  Beams:idB = 11 / eB
WeakBosonExchange:ff2ff(t:gmZ) = on
PhaseSpace:Q2Min = 25.
SpaceShower:dipoleRecoil = on      // required for DIS
SpaceShower:pTmaxMatch = 2
PDF:lepton = off ;  TimeShower:QEDshowerByL = off
```
`SpacelikeShowers.xml:371-381` states the dipole-recoil option "for the first time allows the simulation of Deeply Inelastic Scattering processes in PYTHIA 8", and that **QED radiation off the lepton leg is not implemented** with it — a real limitation for EIC polarized asymmetries, where radiative corrections matter.

**Class chain:**
- `Sigma2ff2fftgmZ`, declared `include/Pythia8/SigmaEW.h:188-215`, implemented `src/SigmaEW.cc:304-651`.
  - `initProc()` `src/SigmaEW.cc:312`
  - `sigmaKin()` `src/SigmaEW.cc:327-338` — γγ/γZ/ZZ propagator pieces
  - **`sigmaHat()` `src/SigmaEW.cc:345-373`** — the flavour-dependent ME, **fully helicity-summed/averaged**: the standard `(v²+a²)(v²+a²)(1+u²/s²) + 4v₁a₁v₂a₂(1−u²/s²)` combination. No λ_lepton, no beam polarization, anywhere.
  - `weightNLO()` `:588-628` and `factRVDIS()` `:378-583` — an inclusive NLO K-factor built from **unpolarized F₂/F_L/F₃** only (`:557-562`, reduced σ at `:578-581`). No g₁, g₂, b₁, A₁, Δq anywhere in the tree.
- Instantiated at `src/ProcessContainer.cc:1650-1651`; beam-combination check at `src/BeamSetup.cc:877-885`.
- **Phase space**: generic `PhaseSpace2to2tauyz` (`include/Pythia8/PhaseSpace.h:339`) — there is **no dedicated DIS (x, Q²) sampler**. `PhaseSpace:Q2Min` enters as `Q2GlobalMin` (`src/PhaseSpace.cc:166-167`, τ limits at `:1158-1163`, z limits `:1232-1233`, cut at `:2204-2205`).

**Where the cross section is assembled** — this is the critical structural fact:

1. `SigmaProcess::sigmaPDF()` — `src/SigmaProcess.cc:414-475`. Loops over **all open flavour channels**, calling `sigmaHatWrap(idA,idB)` (`:452`) and multiplying by each beam PDF, summing into `sigmaSumSave`.
2. `SigmaProcess::sigmaHatWrap` — `include/Pythia8/SigmaProcess.h:142-144`:
   ```cpp
   virtual double sigmaHatWrap(int id1in = 0, int id2in = 0) {
     id1 = id1in; id2 = id2in;
     return ( convert2mb() ? CONVERT2MB * sigmaHat() : sigmaHat() ); }
   ```
   → **`sigmaHat()` sees the struck-quark flavour.**
3. `PhaseSpace::trialKin123` — `src/PhaseSpace.cc:1074` calls `sigmaPDF()`, then **`src/PhaseSpace.cc:1089-1091`** applies `userHooksPtr->multiplySigmaBy(...)` and `biasSelectionBy(...)` **to the flavour-summed total**.
4. Only afterwards, `src/ProcessContainer.cc:490` calls `pickInState()` to choose the flavour.

**Consequence (the single most important finding for injection strategy):** `UserHooks::multiplySigmaBy` (`include/Pythia8/UserHooks.h:43-47`, base impl `src/UserHooks.cc:27-66`) is **flavour-blind**. Since the DIS double-spin asymmetry `A₁ ∝ Σ e_q² Δq / Σ e_q² q` is flavour-dependent, you **cannot** apply the correct polarized weight there. Its arguments are only `SigmaProcess*` and `PhaseSpace*` — you get `x1, x2, Q2Fac, sHat, tHat, uHat`, not `id1/id2`.

Correct injection points, in order of preference:
- **Best: your own `Sigma2Process` subclass via `Pythia::setSigmaPtr`** (`include/Pythia8/Pythia.h:190-195`). Override `sigmaHat()` — you get `id1`, `id2`, `sH/tH/uH`, and you can write the full polarized `dσ/dxdQ²` including the flavour-dependent Δq/q and the lepton helicity. This is the clean, exact route, and it is a documented, supported extension mechanism (`SemiInternalProcesses.xml`, example `examples/main244.cc`).
- `setSigmaPtr`'s **second argument accepts a custom `PhaseSpace`** subclass (`Pythia.h:190-191`, `SemiInternalProcesses.xml:64-70`) — so you can sample directly in (x, Q², φ) rather than τ/y/z, which you'll want for the cos2φ double-helicity-flip term.
- `canVetoProcessLevel` / `doVetoProcessLevel(Event&)` (`UserHooks.h:60-64`, called `src/Pythia.cc:1137`) — takes a **non-const** `Event&`, fires after the hard process + resonance decays, before PartonLevel. Usable for accept/reject reweighting where id1/id2 are known, and for editing the record.
- `canBiasSelection`/`biasSelectionBy`/`biasedSelectionWeight` (`UserHooks.h:50-57`, `PhaseSpace.cc:1091,1138`) — for oversampling high-Q² or high-x, with automatic compensating weights.

## 3. Nuclear beams: what actually happens with `1000030060`

- **6Li and 7Li are in the particle table**: `share/Pythia8/xmldoc/ParticleData.xml:11500` (`1000030060`, m0=5.6030512) and `:11504` (`1000030070`, m0=6.535). `BeamParameters.xml:26-48` explicitly lists `1000030060` as an allowed beam.
- **Two spin values are wrong for your physics.** `spinType` is 2s+1 (`ParticleDataScheme.xml:70-71`). The table has 6Li `spinType="1"` (spin 0 — should be **3**), 7Li `spinType="2"` (spin ½ — should be **4**), 2H `spinType="1"` (should be **3**). Trivially fixed via `readString("1000030060:spinType = 3")`, but nothing in PYTHIA consumes it anyway.
- **There is no nucleus API.** No `isNucleus`/`nucleusA`/`nucleusZ` anywhere; the `10LZZZAAAI` code is decoded ad hoc in 5 places: `src/HeavyIons.cc:394-398`, `src/HINucleusModel.cc:74-98`, `src/PartonDistributions.cc:3903-3907` and `:2272-2277`, `src/BeamSetup.cc:1396`.
- **Any nucleus id silently diverts the whole run into Angantyr** — `src/HeavyIons.cc:394-398` (`abs(id/100000000)==10`), acted on at `src/Pythia.cc:446-457` and `:1006-1012`.
- **`e + A` is not supported in any form.** `src/HeavyIons.cc` and `share/Pythia8/xmldoc/HeavyIons.xml` (1187 lines) contain **zero** occurrences of lepton/electron/DIS/photon/gamma physics. `HeavyIons.xml:63-65` restricts beam switching to "`idA` … any hadron, while `idB` … a proton, nucleon or any ion". Concretely, `Beams:idA=11, idB=1000030070` would enter Angantyr, which replaces the ion by p/n (`src/HeavyIons.cc:633-647`) and configures sub-Pythia instances with SoftQCD for beams (11, 2212) — which then fail `BeamSetup::checkBeams` at `src/BeamSetup.cc:886` ("cannot handle this beam combination"). Nuclei are not hadrons: `ParticleDataEntry::isHadron()` returns false for `idSave >= 9900000` (`src/ParticleData.cc:163-164`).
- **Angantyr is a Glauber MC**: `Angantyr::next()` `src/HeavyIons.cc:2287-2330` — impact parameter, `Nucleus` generation, subcollision model, wounded nucleons (`UNWOUNDED/ELASTIC/DIFF/ABS`), stacked absorptive/diffractive sub-events, then `addNucleusRemnants()`. Remnants get **fabricated** PDG ids `1000000009 + 10000*Zp + 10*A` with mass `A × m_N` and no binding energy (`src/HeavyIons.cc:2082-2106`).
- **Light-nucleus geometry**: `NucleusModel::create` (`src/HINucleusModel.cc:47-56`) offers GLISSANDO(1)/WoodsSaxon(2)/HOShell(3)/Gaussian(4)/Hulthen(5). `HOShellModel` (`:414-462`) is for 4≤A≤16 and **has a built-in charge radius for 6Li (`:432`, 6.4/6.7 fm²) but none for 7Li** — the table jumps 6Li → 7Be → 8Li, so 7Li errors at `:455` unless you set `HeavyIonA:HONuclearChargeRadius` by hand.
- **`ClusterModel` exists but is dead code** — `src/HINucleusModel.cc:722-762`: hard-coded to 4He only (`vector<int> implemented = {1000020040}`), **unreachable** from `create()`, and would null-deref at `:742` (`nModelPtr = unique_ptr<HulthenModel>();` — an empty unique_ptr — then dereferenced at `:743`). **There is no α+d or α+t cluster model.**
- **Nuclear PDFs**: `nPDF`/`Isospin`/`EPS09`/`EPPS16` at `include/Pythia8/PartonDistributions.h:1060/1110/1126/1170`. Isospin averaging `f^A = (Z/A)f^{p/A} + (N/A)f^{n/A}` at `src/PartonDistributions.cc:3930-3963`; A/Z decode at `:3903-3907` (`a=(id/10)%1000; z=(id/10000)%1000` — works for `1000030060` → A=6,Z=3). Plugged in at `src/BeamSetup.cc:1055-1071` and `:1395-1412` via `PDF:useHardNPDFA/B` + `PDF:nPDFBeamA/B`. **Grid files are keyed on A by filename** (`:3995-3996`, `:4164`) and **only `EPS09LOR_208` ships** — nothing for A=6/7. `PDF:nPDFSetA=0` (isospin only) is the sole option that works for arbitrary A. `PDFSelection.xml:333-345` confirms nPDFs are **hard-process only** and give an *average nucleon* — not what you want when you need to know whether you struck a p or an n.

## 4. Extension points

Available as both C++ pointers and runtime plugins (`Plugins.xml:160-178`): `PDF`, `LHAup`, `DecayHandler`, `RndmEngine`, `UserHooks`, `Merging`, `MergingHooks`, `BeamShape`, `SigmaProcess`, `PhaseSpace`, `ResonanceWidths`, `ShowerModel`, `FragmentationModel`, `HeavyIons`, `HIUserHooks`. Loaded at runtime with `Init:plugins = {libMyPlugins.so::MyClass}` (`MainProgramSettings.xml:99-111`) or `make_plugin<Base>(lib, class, pythiaPtr)`; plugin libraries can register their own settings.

Mapping to your five requirements:

**(i) Sample struck nucleon (p/n) from a cluster wave function with Fermi momentum** — no PYTHIA machinery; you do it yourself. Two places it can land: a custom `BeamShape::pick()` (below), or fully externally with `LHAup`.

**(ii) Set its polarization** — `Particle::pol(double)` setter `include/Pythia8/Event.h:115`, getter `:142`, storage `double polSave` `:308`, default `9.` = unknown (`:39`), snapping helper `Particle::intPol()` `src/Event.cc:41-49`. It is carried through `Event::copy` and LHEF SPINUP I/O (`src/ProcessContainer.cc:870,1291`; `src/LesHouches.cc:1480-1481` writes both incoming beams' pol). See §5 for what actually consumes it.

**(iii) Weight events by spin-dependent structure functions** — custom `SigmaProcess::sigmaHat()` via `setSigmaPtr` (only place with flavour resolution), plus optionally a custom `PhaseSpace`. Not `multiplySigmaBy` (§2).

**(iv) Add spectator fragments** — 4He `1000020040`, 2H `1000010020`, 3H `1000010030` all exist in `ParticleData.xml:11484-11497`. Append them to `pythia.event` **after `pythia.next()` returns**, which bypasses PYTHIA's momentum-conservation checks (those run inside `next()`). `include/Pythia8Plugins/PythiaCascade.h` is a proven in-tree template for exactly this pattern (it injects target nucleons with custom status codes 181/182). Alternatively `doVetoProcessLevel(Event&)` (non-const, `src/Pythia.cc:1137`) if you need them present before showering.

**(v) Moving/off-shell target nucleon — this is where the real limits are.**

- `Beams:frameType = 3` gives full 3-momenta for both beams (`BeamParameters.xml:98-127`).
- `Pythia::setKinematics(Vec4, Vec4)` exists (`Pythia.h:283-287`, `src/BeamSetup.cc:319-334`) **but per-event use requires `Beams:allowVariableEnergy`, which aborts with hard processes**: `src/Pythia.cc:662-665`
  ```cpp
  if (beamSetup.doVarEcm && doHardProc) {
    logger.ABORT_MSG("variable energy only works for softQCD processes");
  ```
  confirmed by `BeamParameters.xml:230-235` ("It is not possible to generate other processes with the variable-energy framework, however, and the program will abort if you try").
- **`Beams:allowMomentumSpread` + a custom `BeamShape` DOES work with hard processes.** `BeamShape::pick()` is virtual (`src/BeamShape.cc:62-...`, docs `BeamShape.xml:47-62`, example `examples/main245.cc`); set `deltaPxA/…/deltaPzB` per event, install with `Pythia::setBeamShapePtr` (`Pythia.h:185-186`). It is invoked from `src/Pythia.cc:1078-1079` → `BeamSetup::nextKinematics()` `src/BeamSetup.cc:633-698`, which recomputes `eCM`, `infoPtr->setECM()`, `beamA.newPzE()` and the lab boost matrices.

  **But two hard limits:**
  1. **The beam is forced on-shell at the PDG mass** — `src/BeamSetup.cc:645-648`: `pAnow.e( sqrt(pAnow.pAbs2() + mA*mA) )` with `mA = particleDataPtr->m0(idA)`. A genuinely **off-shell** bound nucleon (m\* ≠ m_p) is not representable.
  2. **The hard-process phase space is not told about the new `s`.** `PhaseSpace::newECM` exists (`include/Pythia8/PhaseSpace.h:58`) but `src/ProcessLevel.cc:645` gates it: `if (eCM != eCMold && doVarEcm)` — and `doVarEcm` is `Beams:allowVariableEnergy` (`src/ProcessLevel.cc:54`), which is mutually exclusive with momentum spread (`src/BeamSetup.cc:492`) and forbidden with hard processes. So with momentum spread the event is generated at the **initialization** `eCM` and merely boosted with the actual beam directions.

  For LHC beam spread (~10⁻⁴) that's irrelevant. **For your case it is not**: Fermi momentum ~0.2 GeV in the nucleus rest frame, boosted by γ≈107 at 100 GeV/u, gives per-nucleon lab momenta spanning ~81–124 GeV — a ±20 % spread in √s. The stale-`s` approximation would be badly wrong.

- **`Beams:newLHEFsameInit`** (`BeamParameters.xml:143-148`) only allows starting a new LHEF/LHAup stream without full re-init; it is not a per-event beam-momentum mechanism. `Beams:allowVertexSpread` is vertex-only.
- **`LHAup` (frameType 5) is the one path with genuine per-event freedom**: `setProcess`, `addParticle`, `setIdX`, `setPdf`, `setScale` (`include/Pythia8/LesHouches.h:243-274`) let you hand PYTHIA the exact incoming/outgoing four-momenta of the hard process each event. `setBeamA/B` (`:222-225`) is init-block-only (a single energy), but the *event* momenta are yours. `examples/main164dis.cmnd` shows DIS-from-LHEF is a tested path (Vincia CKKW-L, `Merging:Process = {e- p > e- j}`).
- `PartonVertex` via `setPartonVertexPtr` (`Pythia.h:269`) — spatial vertices only, no help here.
- `BeamRemnants:unresolvedHadron` (`BeamRemnants.xml:332-341`, implemented `src/BeamParticle.cc:777-782`) collapses a beam remnant back to the **original intact incoming hadron** — literally the "coherent intact recoil" mechanism, built for coherent photon emission off a proton. It requires `isHadronBeam`, so it works on a proton/neutron proxy beam but not on a nucleus id.

## 5. Polarization: what exists

Essentially nothing usable, but one reusable engine.

- **No `Beams:polA`/`polB` or any beam-polarization setting exists.** `ParticleDecays.xml:168-171` states it outright: *"While Pythia does not internally produce events with polarized beams, beam polarization for externally provided events is accounted for in tau decays when the beam SPINUP digits are set accordingly."*
- `Particle::polSave` is an inert `double` (`Event.h:308`). Its only consumers in the core: the weak shower's Z coupling selection (`src/PartonLevel.cc:3042-3050`, `:3212-3217`), tau decays, LHEF I/O, and Vincia's parton-helicity labels. `src/Merging.cc:168,471,644,1480` wipes it to 9.
- **`SigmaProcess` has no helicity concept at all** — zero hits for helicity/spin/pol in `SigmaProcess.{h,cc}`. DIS is helicity-averaged (`src/SigmaEW.cc:345-373`).
- **No polarized PDFs.** Zero polarization hits in `src/PartonDistributions.cc`. No `PDF:polarized`, no Δq machinery. (You would supply these yourself, or via LHAPDF6 sets such as NNPDFpol1.1 / DSSV, loaded through the LHAPDF6 plugin.)
- **No g₁, g₂, b₁, A₁ anywhere.** Only unpolarized F₂/F_L/F₃ inside the NLO K-factor (`src/SigmaEW.cc:557-581`).
- **The one real spin engine**: `HelicityMatrixElements.{h,cc}` + `HelicityBasics.h`. `HelicityParticle` (`include/Pythia8/HelicityBasics.h:182-247`) carries a genuine **helicity density matrix `rho`** (`:234`) and **decay matrix `D`** (`:237`); `pol(hIn)` maps a helicity label into rho (`src/HelicityBasics.cc:377-390`, with `pol()==9` → unpolarized `1/N` average). The Collins–Knowles recursion at **`src/HelicityMatrixElements.cc:146-148`** explicitly folds in **both incoming particles' density matrices**:
  ```cpp
  p[idx].rho[h1[idx]][h2[idx]] += p[0].rho[h1[0]][h2[0]] *
    p[1].rho[h1[1]][h2[1]] * calculateME(h1)*conj(calculateME(h2)) *
    calculateProductD(idx, 2, p, h1, h2);
  ```
  So a polarized beam lepton genuinely propagates into tau spin correlations. **But** every implemented hard ME is s-channel or γγ (`src/TauDecays.cc:302-369`) — there is no t-channel topology, and the machinery only re-weights *decay* orientations; it never touches the production cross section.
- Only pure helicity eigenstates ±1/0 are representable. Partial polarization P must be simulated by sampling ±1 with probability (1±P)/2 — exactly what `TauDecays:tauPolarization` does (`src/TauDecays.cc:194-195`).
- Most-developed helicity code is **Vincia's helicity shower** (`Vincia:helicityShower`, default off, `Vincia.xml:127-131`; kernels `src/VinciaAntennaFunctions.cc:22-180`), including **linear gluon polarization** variants `Pg2ggLin`/`Pg2qqLin`/`Pq2gqLin` (`include/Pythia8/VinciaAntennaFunctions.h:50-55`) — conceptually adjacent to your cos2φ term, though built for showers, not structure functions. Incompatible with merging (`src/VinciaMergingHooks.cc:872-875`). Also `TimeShower:phiPolAsym`/`SpaceShower:phiPolAsym` exist for azimuthal asymmetry from gluon linear polarization.

## 7. Recommended architecture

**Do not fork the core.** Build a standalone C++ library (`libeLiDIS.so`) linking `libpythia8`, exposing itself both as a Pythia plugin library and as its own thin Python module. Concretely:

**Layer A — external nuclear/spin event generator (your code, no PYTHIA involvement).**
Per event, in your own code: sample the cluster configuration (6Li → α+d, 7Li → α+t), the struck nucleon (p or n) and its Fermi momentum from your wave function, the spectator momenta, the nucleus and lepton spin projections, and the DIS kinematics (x, Q², φ) from your polarized cross section including g₁, b₁ and the cos2φ double-helicity-flip gluon term. This is where all the physics you care about lives, and none of it exists in PYTHIA.

**Layer B — hand the hard process to PYTHIA via `LHAup` (`Beams:frameType = 5`).**
This is the decisive choice. `LHAup::setProcess/addParticle/setIdX/setPdf/setScale` (`include/Pythia8/LesHouches.h:243-274`) lets you specify the **exact per-event four-momenta** of the incoming lepton and struck quark, which is the only mechanism in PYTHIA 8.317 that survives a ±20 % per-event beam-momentum swing (§4(v)). Set SPINUP on the incoming lepton and nucleon so `Particle::pol()` is populated (`src/ProcessContainer.cc:870,1291`) and downstream tau/weak-shower code sees it. `Beams:idA = 11`, `Beams:idB = 2212` or `2112` — **never a nucleus id**, which would divert into Angantyr (§3). DIS-from-LHEF is a tested path (`examples/main164dis.cmnd`). Add `Check:beams = off` if you need a nonstandard combination (`ErrorChecks.xml:66-73`).

**Layer C — PYTHIA does showering, hadronization and decays, unmodified.**
`SpaceShower:dipoleRecoil = on`, `SpaceShower:pTmaxMatch = 2`, `PDF:lepton = off`, `TimeShower:QEDshowerByL = off` (`examples/main341.cc:45-54`). Requirement (d) is satisfied with stock settings.

**Layer D — spectators and coherent recoil.**
After `pythia.next()` returns, append 4He/2H/3H/n (all in `ParticleData.xml:11484-11497`) to `pythia.event` with your sampled Fermi momenta. Doing it post-`next()` sidesteps PYTHIA's momentum-conservation checks; `include/Pythia8Plugins/PythiaCascade.h` is the in-tree precedent. For the coherent intact-recoil channel (c), generate it entirely in Layer A and emit an event whose only hadronic content is the intact nucleus — PYTHIA's `BeamRemnants:unresolvedHadron` is the analogous internal mechanism but works only on hadron beams, so it is a design reference rather than something to call.

**Layer E — output.** `Pythia8ToHepMC3::fill_next_event` (`include/Pythia8Plugins/HepMC3.h`) or the `HepMC3Hooks` plugin. Python via the shipped `pythia8` module, with your library wrapped in its own pybind11 module (Python subclasses of `UserHooks`/`LHAup` are supported, `PythonInterface.xml:74-78`).

**Variant, if you prefer PYTHIA's phase-space sampler over your own:**
Instead of Layer B, use `Pythia::setSigmaPtr(mySigma, myPhaseSpace)` with a `Sigma2Process` subclass whose `sigmaHat()` implements the polarized DIS ME (it *does* see `id1`/`id2` — `SigmaProcess.h:142-144`), plus a custom `PhaseSpace` sampling directly in (x, Q², φ). Combine with a custom `BeamShape` for Fermi motion and a custom `PDF` (via `setPDFPtr`) returning polarized/nucleon-specific distributions. This is more elegant and keeps PYTHIA's machinery, **but it inherits the stale-`s` defect** (`src/ProcessLevel.cc:645`) and the on-shell beam-mass constraint (`src/BeamSetup.cc:645-648`), so it is only sound if you can treat Fermi motion as a small perturbation — which at EIC boosts you cannot. Recommend it only for a fixed-frame validation mode, not production.

**What genuinely cannot be done without forking:**
1. **Per-event hard-process √s consistent with a Fermi-smeared beam.** `src/ProcessLevel.cc:645` gates `newECM` on `doVarEcm`, and `src/Pythia.cc:662-665` forbids `doVarEcm` with hard processes. Removing that one gate is a ~2-line core patch; the LHAup route avoids it entirely, which is why it is the recommendation.
2. **A truly off-shell target nucleon.** `src/BeamSetup.cc:645-648` forces `E = √(p²+m₀²)` from the PDG mass. Only LHAup lets you supply arbitrary four-momenta.
3. **Native `e + A` beams.** Would require intercepting `HeavyIons::isHeavyIon` (`src/HeavyIons.cc:394-398`) and teaching `BeamSetup::checkBeams` (`src/BeamSetup.cc:758-890`) about lepton+nucleus. Avoid — use a nucleon proxy beam, which is the pattern PYTHIA itself endorses (`examples/main344.cc:110-127`).
4. **Spin as a first-class quantity in the hard process.** `SigmaProcess` has no helicity interface; you carry polarization in your own Layer A state and only mirror it into `Particle::pol()` for the record.
5. **α+d / α+t cluster geometry inside Angantyr.** `ClusterModel` is 4He-only, unreachable, and crashes (`src/HINucleusModel.cc:722-762`). Since you are not using Angantyr, this is moot.

**Practical setup notes**: configure with `--with-hepmc3 --with-python --with-lhapdf6`; if you ever touch PYTHIA headers, regenerate the Python bindings (`plugins/python/generate --full`). Fix the spin table entries (6Li → `spinType 3`, 7Li → `spinType 4`, 2H → `spinType 3`) and consider correcting 7Li's mass (`6.535` in the table vs ≈6.5335 GeV actual).
